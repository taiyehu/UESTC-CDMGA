# 前端开发：React + TypeScript

当前开发和部署主线是 `reactproject/`；`vueproject/` 为旧版 Vue 实现，保留作历史参考和必要维护，不要把旧工程构建产物当作当前前端发布。

## 从哪里改

- 新页面：`reactproject/src/pages`，并在 `src/App.tsx` 注册路由。
- 可复用区域：`reactproject/src/components`；不要把同一段页面复制多份。
- 后端请求：统一使用 `reactproject/src/api.ts` 中的 Axios 实例和 API 函数。
- 类型：共用接口类型放 `src/api.ts` 或对应模块，少用 `any`。

## 看懂一个 React 页面

页面使用 TSX 函数组件；状态由 React hooks 管理，JSX 描述界面，样式由全局 CSS 与组件 class 配合。

推荐数据流：

```text
用户点击 → React 页面函数 → src/api.ts → /api 后端
                                  ↓
页面状态 ← 解析 Result/错误 ← Axios 返回
```

## 新增一个基础功能的顺序

1. 先确认后端接口方法、路径、参数和返回 JSON。
2. 在 `src/api.ts` 或所属 API 模块新增带类型的函数。
3. 在页面中处理 loading、成功、空数据、错误四种状态。
4. 若是新页面，添加路由和导航入口。
5. 用普通用户和管理员分别测试权限表现。
6. 执行 `pnpm build`；TypeScript 错误必须解决，不能用大量 `as any` 掩盖。

示例接口封装：

```ts
import { api } from './api'

export interface ExampleItem {
  id: number
  name: string
}

export const fetchExamples = () =>
  api.get('/example/list') // 实际请求会是 /api/example/list
```

## 本项目的路由与登录

路由使用 HTML5 history，因此生产 Nginx 必须保留 `try_files $uri $uri/ /index.html`，否则刷新 `/admin/users` 会 404。后端用 HttpOnly Session Cookie 识别登录身份；进入受保护路由时前端请求 `/api/identity/me` 并更新 `sessionStorage` 缓存。该缓存可被用户修改，不能当作登录证明或角色授权依据。

前端路由守卫只控制导航体验，不能保护数据。后端 `ApiAuthorizationInterceptor` 会校验服务端会话并读取数据库角色；任何管理员功能和用户数据访问规则都必须在后端再次执行。

个人主页允许已登录用户查看他人公开资料和已评分课题成绩；待审核/已删除成绩不会作为公开成绩返回。`/score/history` 等提交历史接口只允许本人访问。测试权限时要分别覆盖这两类业务，不能把“提交历史不允许跨用户读取”解释成“他人成绩不可见”。

## UI 开发约定

- 优先复用 `PageShell` 等现有 React 组件与 `src/styles.css` 的主题变量。
- 沿用当前页面的 CSS 布局方式，避免同一属性被多套样式覆盖。
- 图片上传前端有 `imageCompressor.ts`，但后端仍必须校验大小、类型和文件名。
- 日期使用 Day.js，前后端以 `Asia/Shanghai` 为业务时区；测试跨日和开始/结束边界。
- 页面必须有加载中、无数据、失败提示；按钮提交期间应禁用，避免重复提交。

## 验证命令

```powershell
cd reactproject
pnpm build
pnpm test:e2e
```

`pnpm build` 会执行 TypeScript 构建检查，`pnpm test:e2e` 运行 Playwright。全量套件中有 Vue/React 对照用例，需按 `reactproject/tests/README.md` 启动对应本地服务；另用普通用户和管理员验证受保护页面与后端 API。

## 排错技巧

F12 的 Console 看前端异常，Network 看请求。先记录请求 URL、方法、状态码、请求体和响应体：状态 404 多为路径错，400 多为参数错，500 看后端日志，502 多为 Nginx 找不到后端，超时可能是后端/数据库慢或当前 Axios 5 秒超时。
