# 第一次在本地运行：从 WSL 到开发分支

> 本文按 Windows + WSL2 Ubuntu 编写。除明确标注 Windows 操作的地方外，命令均在 **Ubuntu 终端**执行。目标是先在自己的电脑跑通网站，再建立分支开发；远程服务器的安装与维护见 [05-服务器搭建与部署.md](05-服务器搭建与部署.md)。

## 先记住三条原则

1. 本地数据库与生产数据库分开，不使用生产账号或真实个人数据练习。
2. WSL 内的后端、前端、MySQL 要使用 **Linux 版**工具，不混用 Windows 的 Node、pnpm 和路径。
3. 先跑通原始项目，再让 AI 修改代码；提交前看差异，推送功能分支不等于批准上线。

项目当前要求：Java 25、Maven Wrapper 3.9.10、Node 24、pnpm 10.30.0、MySQL 8 系。依据是 [pom.xml](../webpage/pom.xml)、[Maven Wrapper 配置](../webpage/.mvn/wrapper/maven-wrapper.properties)、[前端 package.json](../vueproject/package.json) 与 [部署工作流](../.github/workflows/CD.yml)。MySQL 实际版本要连接后用 SELECT VERSION() 查看。所有 <...> 都是占位符，必须换成自己的值，不能原样照抄。

## 1. 启动 WSL 虚拟环境

在 **Windows PowerShell** 运行：

~~~powershell
wsl -l -v
~~~

确认发行版名称和 VERSION 2。若还没安装，先按 [微软官方 WSL 安装指南](https://learn.microsoft.com/windows/wsl/install)安装，遇到“重启前更改不生效”时先重启电脑。启动时将 Ubuntu 换成自己列表中实际显示的名称：

~~~powershell
wsl -d Ubuntu
~~~

出现 Linux 用户的提示符才进入后续步骤。代码建议放在 Ubuntu 的 /home 目录，不把 Linux 的 Git 仓库和 node_modules 放在 /mnt/c 或 /mnt/d；见 [微软的 WSL 开发环境建议](https://learn.microsoft.com/windows/wsl/setup/environment)。

## 2. 安装基础命令、配置 GitHub SSH、拉取仓库

以下在 **Ubuntu** 运行：

~~~bash
sudo apt update
sudo apt install -y git curl ca-certificates wget gpg mysql-client
git --version
ssh -T git@github.com
~~~

若 SSH 尚未配置，先检查 ~/.ssh/id_ed25519 是否已经存在；已有密钥不要覆盖。没有时可在 WSL 运行 ssh-keygen -t ed25519 -C "你的 GitHub 邮箱"，按提示选择保存位置和密码。再运行 cat ~/.ssh/id_ed25519.pub，**只复制这一行公钥**到 GitHub 的 Settings → SSH and GPG keys → New SSH key；绝不展示或上传没有 .pub 后缀的私钥。随后重试 ssh -T git@github.com，看到 GitHub 的认证成功提示即可（该检查可能仍返回非零退出码）。完整步骤见 [GitHub 的 SSH 指南](https://docs.github.com/authentication/connecting-to-github-with-ssh/about-ssh)。Windows 上已有的 GitHub SSH 配置不会自动等于 WSL 的配置。确认自己拥有仓库访问权限后：

~~~bash
mkdir -p ~/project
cd ~/project
git clone git@github.com:taiyehu/UESTC-CDMGA.git
cd UESTC-CDMGA
git remote -v
git status --short
~~~

新克隆的工作区通常应是干净的；如果出现不认识的修改，不要清理或覆盖。以下统一使用 ~/project/UESTC-CDMGA 作为示例，个人路径不同应整体替换。首次提交前设置自己的 Git 身份，例如运行 git config --global user.name "你的名字" 和 git config --global user.email "你的 GitHub 邮箱"。

### 在 VS Code 中打开 WSL 仓库

先在 **Ubuntu 终端**确认位置，避免误打开 Windows 上的另一份仓库：

~~~bash
cd ~/project/UESTC-CDMGA
pwd
git rev-parse --show-toplevel
git status --short
~~~

前两个路径应指向 /home/你的用户名/project/UESTC-CDMGA。推荐在 **Windows** 安装 VS Code 和 WSL 扩展，然后在上述 Ubuntu 目录运行 `code .`；打开后检查 VS Code 左下角是否显示 `WSL: Ubuntu`，集成终端里的 `pwd` 是否仍指向这份仓库。此方式下终端、Git 和安装在 WSL 的开发扩展都在 Linux 环境运行。VS Code 首次连接会下载 VS Code Server；若安装失败，可先从 Windows VS Code 的命令面板运行 `WSL: Connect to WSL using Distro...`，选择实际的发行版，再打开 /home/你的用户名/project/UESTC-CDMGA。排错时用 `WSL: Open Log` 查看完整原因。参考 [VS Code WSL 指南](https://code.visualstudio.com/docs/remote/wsl)及[官方排错说明](https://code.visualstudio.com/docs/remote/troubleshooting)。

**临时方案：Server 装不上时，仅用 Windows VS Code 编辑 WSL 文件。** 在 Windows VS Code 选择 File → Open Folder，输入 `\\wsl.localhost\Ubuntu\home\你的用户名\project\UESTC-CDMGA`；发行版名称用 Windows PowerShell 的 `wsl -l -v` 核对，路径用 Ubuntu 的 `pwd` 核对。如果提示“在 WSL 中重新打开”，暂时不要选。此时 VS Code 主要用于查看和手动编辑文件，AI Agent Pi 则按第 11 节在**独立的 Ubuntu 终端**运行。不要在 Windows 终端的 UNC 路径上运行 `pnpm`、`./mvnw`、MySQL 或 Git；CMD 不支持把 UNC 路径作为当前目录，可能再次出现 `vite: not found` 等错误。Windows 直接访问 WSL 文件也可能较慢。参考 [微软的 WSL 文件访问说明](https://learn.microsoft.com/windows/wsl/interop)。

无论用哪种方式，交给 AI 前都先确认当前打开的仓库路径与 `git status --short`；明确要求它只处理指定文件、不要读取或输出密码、不自行连接生产环境。修改后在 Ubuntu 终端检查 `git diff`，按第 12 节构建和提交。**打开了 WSL 文件夹，不等于另一份 Windows 仓库会自动同步。**

## 3. 安装 Java 25，验证 Maven Wrapper

不要误用 Ubuntu 自带的 Java 17/21。可按 [Eclipse Adoptium 的 Ubuntu 安装说明](https://adoptium.net/installation/linux)配置软件源并安装：

~~~bash
sudo apt install -y wget apt-transport-https gpg
wget -qO - https://packages.adoptium.net/artifactory/api/gpg/key/public | gpg --dearmor | sudo tee /etc/apt/trusted.gpg.d/adoptium.gpg > /dev/null
. /etc/os-release
echo "deb https://packages.adoptium.net/artifactory/deb $VERSION_CODENAME main" | sudo tee /etc/apt/sources.list.d/adoptium.list
sudo apt update
sudo apt install -y temurin-25-jdk
java -version
~~~

再检查项目自己的 Maven；首次运行 Maven Wrapper 需要下载依赖，可能耗时较长：

~~~bash
cd ~/project/UESTC-CDMGA/webpage
./mvnw -version
~~~

应看到 Maven 3.9.10 和 Java 25。不必单独全局安装 Maven，不要用 sudo 运行项目构建。

## 4. 在 WSL 安装 Node 24、npm、pnpm 10.30.0 和前端依赖

先看 Node 和 pnpm 的来源：

~~~bash
type -a node
type -a npm
type -a pnpm
node --version
~~~

路径如果在 /mnt/c、/mnt/d，或输出出现 CMD.EXE、wsl.localhost UNC 路径，说明 WSL 调用了 Windows 版工具。下面把安装分成三层：**先安装 Node.js 24（同时取得 npm）→ 用 npm 安装 pnpm 10.30.0 → 用 pnpm 安装本项目依赖**。npm 是安装 pnpm 的工具；日常运行本项目则使用 pnpm。

### 4.1 安装 WSL 内的 Node.js 和 npm

若 nvm 下载困难，可按 [NodeSource 说明](https://github.com/nodesource/distributions)安装 WSL 内的 Node 24。先下载 24.x 软件源配置脚本；只有下载成功才执行后续命令，不要在下载失败后直接运行 apt install nodejs，否则可能仍装到 Ubuntu 默认的旧版本：

~~~bash
curl -fsSL https://deb.nodesource.com/setup_24.x -o /tmp/nodesource_setup_24.x.sh
sudo -E bash /tmp/nodesource_setup_24.x.sh
sudo apt install -y nodejs
hash -r
node --version
node -p "process.execPath"
npm --version
type -a npm
~~~

应看到 Node v24，node 和 npm 都来自 Linux 路径。**这套 Node.js 安装流程同时安装 npm，无需再单独运行 apt install npm。** 如果 node 仍是 18，先用 apt-cache policy nodejs 和 type -a node 检查软件源与实际路径；如果 node 是 24 但 npm 命令不存在，先核对 NodeSource 安装是否成功，不要混装 Ubuntu 默认的 npm 包。Node 与 npm 的关系见 [npm 官方安装说明](https://docs.npmjs.com/downloading-and-installing-node-js-and-npm/)。

### 4.2 用 npm 安装 pnpm

先运行 pnpm --version。若命令不存在或版本不是项目固定的 10.30.0，在 **WSL Ubuntu** 中执行：

~~~bash
sudo npm install --global pnpm@10.30.0
hash -r
pnpm --version
type -a pnpm
~~~

这里的 sudo 是因为本节的 Node.js 安装在系统目录；若你改用 nvm 在个人目录安装 Node，则运行 npm install --global pnpm@10.30.0 即可，不加 sudo。pnpm 应显示 10.30.0，且路径不能指向 Windows 的 /mnt/c 或 .cmd。不要直接安装无版本号的最新 pnpm，本项目的 [package.json](../vueproject/package.json) 固定了 10.30.0；[pnpm 官方文档](https://pnpm.io/installation/)也说明了 Node 24 的兼容性。

### 4.3 用 pnpm 安装项目依赖

最后进入前端目录，从 pnpm-lock.yaml 安装 Vue、Vite 等项目依赖并构建：

~~~bash
cd ~/project/UESTC-CDMGA/vueproject
pnpm install --frozen-lockfile
pnpm build
~~~

不要在本项目改用 npm install，也不要删 pnpm-lock.yaml。若以前用 Node 18 或 Windows pnpm 安装过，先确认 Node 24 生效，再运行 pnpm install --force --frozen-lockfile 重装当前项目依赖。

## 5. 安装、启动本地 MySQL

让 MySQL 与后端先运行在同一套 WSL Ubuntu 中，减少 Windows/WSL 网络差异：

~~~bash
sudo apt install -y mysql-server
sudo systemctl status mysql --no-pager
~~~

若已安装但未运行，在 **自己的 WSL** 中启动：

~~~bash
sudo systemctl start mysql
sudo systemctl status mysql --no-pager
~~~

预期 active (running)。直接运行 mysql 报 ERROR 2002、找不到 mysqld.sock，表示客户端尚未通过本地 socket 连上服务；先检查服务状态，不要先重设密码。若 systemctl 不可用，尝试 sudo service mysql status；启动失败看 sudo journalctl -u mysql -n 80 --no-pager。参见 [MySQL 安装说明](https://dev.mysql.com/doc/refman/8.4/en/linux-installation-apt-repo.html)。

## 6. 创建本地开发库和应用用户

仅在本机执行。先以本地管理员进入 MySQL：

~~~bash
sudo mysql
~~~

出现 mysql> 后，把两处 <本地强密码> 换成相同的新密码，执行：

~~~sql
SELECT VERSION();
CREATE DATABASE CDMGA CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'cdmga_dev'@'localhost' IDENTIFIED BY '<本地强密码>';
CREATE USER 'cdmga_dev'@'127.0.0.1' IDENTIFIED BY '<本地强密码>';
GRANT ALL PRIVILEGES ON CDMGA.* TO 'cdmga_dev'@'localhost';
GRANT ALL PRIVILEGES ON CDMGA.* TO 'cdmga_dev'@'127.0.0.1';
SHOW GRANTS FOR 'cdmga_dev'@'127.0.0.1';
exit
~~~

这里仅授权本地 CDMGA 库，不给全局权限，也不用 % 放开任意来源；cdmga_dev 是**用户名**，不是数据库名。Linux 上库名大小写可能有区别，后续连接和导入都保持大写 CDMGA。如果提示库或用户已存在，先确认是否为旧练习数据，不直接 DROP。退出管理员后，用应用账号验证：

~~~bash
mysql --protocol=TCP -h 127.0.0.1 -P 3306 -u cdmga_dev -p CDMGA
~~~

密码在提示符中输入，不会显示字符。进入 mysql> 后：

~~~sql
SELECT CURRENT_USER(), DATABASE(), VERSION();
SHOW TABLES;
exit
~~~

DATABASE() 应为 CDMGA；CURRENT_USER() 显示实际匹配的 用户@主机。刚建好的空库没有表是正常的。

## 7. 导入开发数据库结构和数据

请维护者提供**确认过、脱敏、适合当前代码的开发基线 SQL**。仓库 sql_script 里混有历史建表、增量脚本和完整导出，不能全部依次执行。带 DROP TABLE 的文件会覆盖目标库里的同名表；只在新空库导入，并事先确认目标库名。

把维护者提供的脱敏文件放在**仓库外**的 ~/project-data 目录；若文件先下载到 Windows，可用 wslpath 'C:\Users\<Windows用户名>\Downloads\文件名.sql' 查出 WSL 路径，再复制到该目录。假设最终文件名为 ~/project-data/CDMGA_baseline.sql：

~~~bash
mkdir -p ~/project-data
ls -lh ~/project-data/CDMGA_baseline.sql
mysql --protocol=TCP -h 127.0.0.1 -P 3306 -u cdmga_dev -p --default-character-set=utf8mb4 CDMGA < ~/project-data/CDMGA_baseline.sql
~~~

成功后重新连接，运行 SHOW TABLES;，再用 SELECT COUNT(*) 等查询核对必要的表和记录数，不展示用户明细。没有脱敏基线时，先停在“空库能连接”的状态；Hibernate 可在临时练习库生成部分结构，但不保证全部索引、外键或演示数据。

此前完整导出因先建 bingo_tips、后建它引用的 issue，遇到 ERROR 1822。重排文件在原作者电脑的 output/cdmga_ordered.sql，但 output 已被 Git 忽略，**新克隆的仓库里没有它**；即使顺序修好了，含真实记录的导出也不能直接作为新人培训数据。请维护者生成脱敏基线。导入中途失败时不要盲目重跑含 DROP TABLE 的脚本，先保存第一条错误。

## 8. 在仓库外建立本地后端覆盖配置

**webpage/src/main/resources/application.properties 保持由 Git 跟踪。** 不要把本地密码写回该文件，也不要在确认数据库指向本机之前启动后端。若历史版本曾出现真实连接信息，维护者需另行清理和轮换；新人不使用它们。

在自己的 WSL 用户目录建立外部配置：

~~~bash
mkdir -p ~/.config/cdmga
nano ~/.config/cdmga/application.properties
~~~

编辑为以下仅供本地使用的内容。nano 中按 Ctrl+O、Enter 保存，Ctrl+X 退出；随后运行 chmod 600 ~/.config/cdmga/application.properties，只允许自己读取。上传文件放在仓库外的个人目录，避免误提交：

~~~properties
spring.datasource.url=jdbc:mysql://127.0.0.1:3306/CDMGA?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai
spring.datasource.username=cdmga_dev
spring.datasource.password=${SPRING_DATASOURCE_PASSWORD}
spring.profiles.active=dev
spring.jpa.hibernate.ddl-auto=validate
server.port=8080
course.upload.directory=${CDMGA_UPLOAD_ROOT}/images/
score.upload.directory=${CDMGA_UPLOAD_ROOT}/scores/
avatar.upload.directory=${CDMGA_UPLOAD_ROOT}/avatars/
activity.upload.banner-directory=${CDMGA_UPLOAD_ROOT}/banners/
activity.upload.file-directory=${CDMGA_UPLOAD_ROOT}/files/
forum.upload.directory=${CDMGA_UPLOAD_ROOT}/forum/
~~~

已导入完整结构时，validate 只核对数据库结构，不自动修改。若失败，先确认基线与代码是否匹配；不要对含真实记录的库随意改用 update。仅在可随时重建的纯本地空练习库，才由维护者决定是否临时用 update 生成基础表。

## 9. 启动后端、前端并做第一次验收

第一个 Ubuntu 终端设置本地密码。变量名必须与第 8 步一致；设置 DB_PASSWORD **不会替代** SPRING_DATASOURCE_PASSWORD：

~~~bash
read -r -s -p '本地 CDMGA 库的 cdmga_dev 用户密码: ' SPRING_DATASOURCE_PASSWORD
echo
export SPRING_DATASOURCE_PASSWORD
export SPRING_CONFIG_ADDITIONAL_LOCATION="file:$HOME/.config/cdmga/"
export CDMGA_UPLOAD_ROOT="$HOME/.local/share/cdmga/uploads"
test -n "$SPRING_DATASOURCE_PASSWORD" && echo "数据库密码变量已设置"
cd ~/project/UESTC-CDMGA/webpage
mkdir -p "$CDMGA_UPLOAD_ROOT"/images "$CDMGA_UPLOAD_ROOT"/scores "$CDMGA_UPLOAD_ROOT"/avatars "$CDMGA_UPLOAD_ROOT"/banners "$CDMGA_UPLOAD_ROOT"/files "$CDMGA_UPLOAD_ROOT"/forum
./mvnw spring-boot:run -P dev
~~~

不要关闭后端终端。看到 Started WebpageApplication 后，在另一个 Ubuntu 终端用 curl -i http://127.0.0.1:8080/hello 检查 HTTP 服务。HTTP 有响应还不能证明所有数据库功能都正确。

第二个 Ubuntu 终端启动前端：

~~~bash
cd ~/project/UESTC-CDMGA/vueproject
node --version
pnpm --version
pnpm dev
~~~

浏览器打开 http://localhost:8081；用 F12 的 Network 面板确认业务请求访问 /api/...，本地 [Vite 配置](../vueproject/vite.config.ts)会转发到后端 8080。用**纯测试账号**注册、登录、退出，确认数据写入本地库。不输入真实用户信息。

## 10. 常见报错速查

| 现象 | 应先检查什么 |
|---|---|
| ERROR 2002、找不到 mysqld.sock | MySQL Server 是否安装和运行。这发生在验证账号密码之前。 |
| ERROR 1045、Access denied for user | 对照错误中的 用户@主机、本地密码和授权。using password: YES 只表示传了密码；先用第 6 步的 CLI 独立连接。 |
| Maven 只显示 BUILD FAILURE、exit code 1 | 那是最终汇总。向上找第一条 APPLICATION FAILED TO START 或 Caused by；核对 Java、数据库、覆盖配置和同终端的密码变量。 |
| Node 18 不符合 Vite 要求 | node --version 与 node -p "process.execPath" 应显示 WSL 内的 Node 24。 |
| pnpm dev 出现 CMD.EXE、wsl.localhost UNC 路径 | WSL 调用了 Windows 版 pnpm；用 type -a node npm pnpm 检查路径。 |
| vite: not found | 在 vueproject 中先成功运行 pnpm install --frozen-lockfile。 |
| Tailwind 报 Cannot find native binding | 先确认 Node 24，再运行 pnpm install --force --frozen-lockfile；不要改用 npm install 或删除 pnpm-lock.yaml。 |
| SQL 报 ERROR 1822、issue_tip 缺索引 | 检查是否在非空旧库留下错误结构；确认文件先建有 issue_id 索引的 issue，再建 bingo_tips。 |
| 浏览器接口 404 / 500 | F12 查看请求地址和状态，再查后端最早异常；不要随意移除 /api 前缀。 |

发送报错给维护者或 AI 时，给**最早的异常及前后文**，遮住密码、Cookie、Session、真实用户数据；不要只截 Maven 最后的 BUILD FAILURE。

## 11. 基线跑通后建立任务分支，使用 AI Agent

在根目录先看状态，再从最新 main 开一条任务分支：

~~~bash
cd ~/project/UESTC-CDMGA
git status --short
git switch main
git pull --ff-only origin main
git switch -c feat/简短任务名
~~~

一项任务一条分支，不直接在 main/dev 试验。如果工作区有不认识的改动，先确认归属。先按第 2 节确认仓库位于 WSL；Pi 在 Ubuntu 终端运行，不依赖 VS Code Server。VS Code 可以同时打开这份文件夹供你审查代码。

### Pi Agent 基础教学：在 WSL 仓库中使用

Pi 是运行在终端中的编程 Agent，可以读取、修改文件并运行命令。它会使用启动它的 Linux 用户所能访问的文件和网络服务，所以要在 **Ubuntu 的仓库根目录**启动，不要在 Windows 终端的 `\\wsl.localhost\...` 路径中启动。Pi 的安装方式和行为以 [官方快速开始](https://pi.dev/docs/latest/quickstart)、[模型与登录指南](https://pi.dev/docs/latest/models)及[安全指南](https://pi.dev/docs/latest/security)为准。

另开一个**新的 Ubuntu 终端**，不要沿用第 9 节设置过数据库密码环境变量的后端终端。先确认 `node --version` 是第 4 节安装的 Linux 版 Node 24，再安装 Pi。官方 Linux 安装器会固定依赖；只从官方地址获取，不使用不明镜像或脚本：

~~~bash
cd ~/project/UESTC-CDMGA
pwd
git status --short
node --version
curl -fsSL https://pi.dev/install.sh | sh
pi --version
~~~
