# 第一次在本地运行

## 1. 安装软件

推荐 Windows 11 + VS Code；也可用 Ubuntu/WSL2。安装 Git、JDK 25、Node.js 24、MySQL 8 系。项目自带 Maven Wrapper 3.9.10，不强制全局安装 Maven。前端使用 pnpm 10.30.0；如果同时使用 Windows 和 WSL，初学时建议让 MySQL 与后端先运行在同一环境，避免跨环境网络问题。

在 Windows PowerShell 验证（如果 `pnpm --version` 已是 10.30.0，可跳过安装那一行；在 WSL/Linux 中改用 `./mvnw -version`，并按实际路径切换目录）：

```powershell
git --version
java -version
node --version
npm --version
cd D:\projects\webpage\webpage
.\mvnw.cmd -version
cd ..\vueproject
npm install --global pnpm@10.30.0
pnpm --version
mysql --version
```

预期：Java 主版本为 25，Node 主版本为 24，Maven Wrapper 使用 Maven 3.9.10，pnpm 为 10.30.0。`mysql --version` 只显示**客户端**版本，数据库服务器版本稍后用 `SELECT VERSION()` 查看。若 `mysql` 命令不存在，检查 MySQL 客户端是否安装及其 `bin` 目录是否在 PATH；不要因此误判 MySQL 服务没启动。版本明显不同先不要继续。

## 2. 准备本地数据库

以下只操作**自己的本机 MySQL**，不要连接生产数据库、不要使用生产数据库账号。安装 MySQL Server 时为本机管理员设置强密码，记下本机监听端口（下文按默认 3306 举例），不要开放到公网。安装后先确认服务已运行：Windows PowerShell 可运行 `Get-Service -Name 'MySQL*'` 查看实际服务名；Ubuntu/WSL 可运行 `sudo systemctl status mysql`（若未启用 systemd，按安装方式检查服务）。如服务未启动，先确认安装和服务名，再按本机方式启动，不要对远程服务器执行。

打开终端，用本地 MySQL 管理员进入 SQL 提示符：

```powershell
mysql -u root -p
```

输入的是**本地** root 密码，终端不显示输入字符是正常现象。某些 Ubuntu 安装使用系统账号认证，可在该 Ubuntu 环境中运行 `sudo mysql`；不要把 `root` 的密码写在命令行参数里。看到 `mysql>` 后执行以下 SQL，将两处 `<本地强密码>` 换成相同、仅用于本地的密码：

```sql
CREATE DATABASE cdmga_dev CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'cdmga_dev'@'localhost' IDENTIFIED BY '<本地强密码>';
CREATE USER 'cdmga_dev'@'127.0.0.1' IDENTIFIED BY '<本地强密码>';
GRANT ALL PRIVILEGES ON cdmga_dev.* TO 'cdmga_dev'@'localhost';
GRANT ALL PRIVILEGES ON cdmga_dev.* TO 'cdmga_dev'@'127.0.0.1';
SHOW GRANTS FOR 'cdmga_dev'@'127.0.0.1';
```

这里的 `ALL PRIVILEGES` **只针对本地练习库 `cdmga_dev.*`**，不是给整个 MySQL 服务器授权；没有使用 `%` 允许任意来源登录。如果提示库或用户已经存在，不要直接 `DROP`，先让维护者确认是否为已有的练习数据。

输入 `exit` 退出管理员会话，然后用**应用账号**重新连接，确认它真的能访问目标库：

```powershell
mysql --protocol=TCP -h 127.0.0.1 -P 3306 -u cdmga_dev -p cdmga_dev
```

看到 `mysql>` 后运行：

```sql
SELECT CURRENT_USER(), DATABASE(), VERSION();
```

`DATABASE()` 应是 `cdmga_dev`；`CURRENT_USER()` 显示 MySQL 实际匹配到的 `用户@主机`；`VERSION()` 显示服务器版本。能在这里成功登录，再启动后端，排错会容易得多。

`sql_script` 同时存在历史建表脚本、增量脚本和包含实际数据的完整导出，不能把它们全部依次执行。新建空库时应由维护者提供一份确认过且脱敏的基线脚本；在此之前可让 Hibernate 创建基础结构，但结果未必涵盖所有索引和外键。不要把生产库导出直接导入练习库。

## 3. 创建仅供本机使用的后端配置

当前 `webpage/src/main/resources/application.properties` 被 `.gitignore` 忽略但已存在于工作区。**先检查并替换其中现有的数据库地址、用户名和密码；不要让本地练习程序连接生产库。**只改本地文件，不提交密码，不把原文件全文发给 AI。将数据库连接项改成类似下面的内容；其他设置按需保留：

```properties
spring.datasource.url=jdbc:mysql://127.0.0.1:3306/cdmga_dev?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai
spring.datasource.username=cdmga_dev
spring.datasource.password=${DB_PASSWORD}
spring.jpa.hibernate.ddl-auto=update

course.upload.directory=${UPLOAD_IMAGES:./local-upload/images/}
score.upload.directory=${UPLOAD_SCORES:./local-upload/scores/}
avatar.upload.directory=${UPLOAD_AVATARS:./local-upload/avatars/}
activity.upload.banner-directory=${UPLOAD_BANNERS:./local-upload/banners/}
activity.upload.file-directory=${UPLOAD_FILES:./local-upload/files/}
```

`DB_PASSWORD` 是环境变量，不是字面密码。启动后端的**同一个 PowerShell 窗口**先输入密码（不会回显，也不会把密码写入命令历史）：

```powershell
$dbSecret = Read-Host '本地 cdmga_dev 密码' -AsSecureString
$env:DB_PASSWORD = [System.Net.NetworkCredential]::new('', $dbSecret).Password
Remove-Variable dbSecret
```

这个环境变量只供当前终端及其启动的子进程使用；关闭终端后需重新设置。在 WSL/Linux 中运行后端时，要在**该 Linux 环境**设置 `DB_PASSWORD`，Windows PowerShell 的环境变量不会自动传过去。Windows 无法直接写 `/var/webserver/...`，因此本地还必须改上传目录并创建这些文件夹。启动目录为 `webpage` 时，相对路径位于 `webpage/local-upload`。

## 4. 启动后端

在第 3 节设置过 `DB_PASSWORD` 的**同一个终端**启动后端；如果已打开新终端，先重新设置该环境变量：

```powershell
cd D:\projects\webpage\webpage
.\mvnw.cmd spring-boot:run
```

看到类似 `Started WebpageApplication` 后不要关闭终端。访问 `http://localhost:8080/hello`；有响应说明 HTTP 服务已启动，但还应实际注册一个测试账号来验证数据库读写。若数据库连接失败，先用第 2 节的 MySQL 命令独立验证连接，再检查后端日志最早的错误。

## 5. 启动前端

打开第二个终端：

```powershell
cd D:\projects\webpage\vueproject
pnpm install --frozen-lockfile
pnpm dev
```

首次安装如提示批准构建脚本，运行 `pnpm approve-builds`，审阅后批准项目实际依赖，再执行 `pnpm rebuild`。浏览器打开 `http://localhost:8081`。

## 6. 第一次验收

- 后端终端没有持续红色异常。
- 前端终端显示 Local 地址且浏览器能打开登录页。
- 浏览器按 F12 → Network，业务请求发往 `/api/...`，状态不是连接失败。
- 注册一个纯测试账号并能登录；不要使用生产账号或真实个人信息。
- 修改代码前执行一次 `pnpm build` 和后端测试，记录原始失败，避免把旧问题误认为自己造成。

## 常见启动错误

### `ERROR 1045 (28000): Access denied for user ...` 怎么办？

这表示请求**已到达 MySQL，但账号、密码、来源主机或授权匹配失败**；通常不是“镜像源问题”，也不是缺少数据库表。`using password: YES` 只说明传了密码，**不代表密码正确**。按以下顺序处理，千万不要为了消除错误而开放 `%` 来源或授予全库管理员权限：

1. 先看错误里的 `'<用户>'@'<主机>'`：是否真是本地练习账号 `cdmga_dev`？如果仍是生产账号，先停止后端并检查 `application.properties`、环境变量、当前 Maven Profile；不要继续尝试生产密码。
2. 复制第 2 节的 `mysql --protocol=TCP -h 127.0.0.1 -P 3306 -u cdmga_dev -p cdmga_dev` 单独测试。密码在提示符输入，不加在命令后面。如果这里也报 1045，先解决 MySQL 账号问题；如果这里成功而 Java 失败，重点检查 JDBC URL、`DB_PASSWORD` 是否在**启动后端的同一终端**设置，以及是否有其他配置覆盖。
3. 用本地管理员登录，执行 `SELECT user, host FROM mysql.user WHERE user = 'cdmga_dev';`，再对实际使用的 `用户@主机` 执行 `SHOW GRANTS FOR 'cdmga_dev'@'127.0.0.1';`。错误中出现 `localhost` 或 `127.0.0.1` 时要认真对照：MySQL 权限是按 `用户@来源主机` 匹配的，不是只看用户名；可用成功连接后的 `SELECT CURRENT_USER();` 确认匹配项。
4. 若只是本地练习账号密码忘了，由本地管理员对**对应主机项**执行 `ALTER USER 'cdmga_dev'@'127.0.0.1' IDENTIFIED BY '<新的本地强密码>';`，必要时也同步修改 `@'localhost'`；随后更新本机 `DB_PASSWORD`，重新测试 CLI，再启动后端。若账号不存在，由管理员按第 2 节创建；不要用 `DROP USER` 清理不认识的账号。
5. 如果连本地管理员也进不去，联系维护者按 MySQL 官方恢复流程处理；不要未经授权使用 `--skip-grant-tables`、开放远程 root 或直接修改生产库。

若错误是 `Can't connect`/连接超时，则先查 MySQL 服务、主机和端口；若是 `Unknown database`，查库名及是否已创建。它们与 1045 不是同一类问题。

| 现象 | 原因/处理 |
|---|---|
| 8080/8081 已被占用 | 关闭旧进程，或查占用：`Get-NetTCPConnection -LocalPort 8080` |
| `pnpm` 不存在 | 确认 Node/npm 可用，在本机运行 `npm install --global pnpm@10.30.0`，再用 `pnpm --version` 验证 |
| 前端请求 500 | 看后端终端最早的 `Caused by`，通常是数据库/数据问题 |
| 前端请求 404 | 检查 API 地址和 Controller 映射，不要随意删 `/api` |
| CORS 报错 | 确认前端从 8081 访问，后端 dev 配置允许该来源 |
| 上传失败 | 检查本地上传目录存在且可写；生产还要检查 Nginx 限制 |
